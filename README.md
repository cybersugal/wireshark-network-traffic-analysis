# wireshark-network-traffic-analysis
Network traffic analysis lab using Wireshark and tcpdump to investigate DNS queries, TCP connections, and network behaviour.
# Network Traffic Analysis with Wireshark

## Overview
A beginner cybersecurity lab focused on capturing and analyzing network traffic generated by my own MacBook during normal web browsing.

## Objectives
- Capture network traffic using Wireshark.
- Identify DNS queries and responses.
- Examine TLS handshake messages and understand the limits of encrypted traffic analysis.
- Inspect TCP connection behavior and flags.
- Explore ICMP diagnostic traffic where available.
- Document observations and findings in a reproducible investigation report.

## Tools
- Wireshark
- macOS
- Terminal (for optional ping testing)

## Methodology
1. Captured my own network traffic while browsing websites.
2. Saved the capture in PCAPNG format.
3. Applied Wireshark display filters to examine different protocols.
4. Inspected packet headers and protocol details.
5. Recorded observations and documented limitations.

## Display Filters Used

| Purpose | Filter |
|---|---|
| DNS investigation | `dns` |
| TLS traffic | `tls` |
| TLS Client Hello | `tls.handshake.type == 1` |
| TCP traffic | `tcp` |
| TCP SYN packets | `tcp.flags.syn == 1` |
| TCP retransmissions | `tcp.analysis.retransmission` |
| ICMP traffic | `icmp` |

## Findings
- DNS: Observed a DNS response for www.wikipedia.org, which resolved through dyna.wikimedia.org to the IP address 103.102.166.224
- TLS: Inspected TLS traffic where a Server Hello, Change Cipher Spec, and Application Data packet was observed (Frame 2654), along with subsequent encrypted application data packets.
- TCP: Used the tcp display filter to inspect TCP packets, observing TCP segments featuring ACK and PSH, ACK flags (with a payload length of 1400 bytes, sequence numbers, and window sizing).
- ICMP: Observed multiple ICMP messages in the capture indicating Destination unreachable (Port unreachable) sent from 192.168.1.73 to destination IPs such as 172.248.216.68 and 172.248.216.69

## Limitations
TLS encryption prevented direct inspection of ordinary HTTPS application contents. A hostname was not assumed from an IP address alone. Findings describe the captured traffic and do not independently establish malicious activity.

## Safety and Scope
All traffic was generated during normal browsing on my own MacBook. No third-party devices were targeted. Sensitive network information and raw captures are not included in this public repository.
